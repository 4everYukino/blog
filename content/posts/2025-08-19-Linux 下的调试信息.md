### 背景

由于并不完全熟悉司内 Makefile 框架，某天想调试代码时发现看不到符号信息。

我确认了 `-g` 被传入了，一开始没找到原因，通过 `file` 查看才发现它被 strip 了。

现在温习一下相关知识。

### 通过 `file` 查看（简洁）

带 `-g` 以及不带 `-g`，分别编译出两个程序，然后通过 `file` 查看之：

```
➜  debug g++ main.cpp --std=c++17 -o main
➜  debug file ./main
./main: ELF 64-bit LSB pie executable, x86-64, version 1 (GNU/Linux), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=1ba4ed5c82a0164c4e970a54e753061b8b509541, for GNU/Linux 3.2.0, not stripped
➜  debug g++ main.cpp --std=c++17 -g -o main
➜  debug file ./main
./main: ELF 64-bit LSB pie executable, x86-64, version 1 (GNU/Linux), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=331b40a4dd82f199aa27d94560cd9ac66b64ec78, for GNU/Linux 3.2.0, with debug_info, not stripped
```

可以非常直观地看到是否 `with debug_info`。

### 通过 `readelf` 查看（详细）

> **ELF（Executable and Linkable Format）** 是一种标准的可执行文件、目标文件和共享库文件格式，广泛用于 Linux、Unix 以及类 Unix 系统。它的作用是让操作系统和编译器能够统一处理可执行程序、目标文件以及共享库。

通过 `readelf` 可以轻松读到上述信息，再通过 grep 来判断即可，步骤一般为：

1. 检查 debug 信息： `readelf -S ./main | grep debug`
2. 检查全局符号： `readelf -S ./main | grep symtab`
3. 检查动态链接符号： `readelf -S ./main | grep dynsym`

另外，若该文件被 strip，那么 1、2 将不复存在，3 则依然能看见。
